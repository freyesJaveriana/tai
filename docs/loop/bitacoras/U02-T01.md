### Decisiones y supuestos
- **Código 4 y la regla «sin leer salidas»:** la tarea dice «si la CLI no dio 0, no lee ninguna salida» y el caso sonda 2 pide imprimir el estado `error` con la CLI en 4. Con 4 solo se lee `estado` (nunca `hallazgos`) y solo se imprime el de los archivos en `error`, con 0 hallazgos. Con otros códigos no se lee nada. Si el orquestador quiere la lectura literal, se quita esa rama y su prueba.
- **CLI en 0 con un archivo en `error`** (p. ej. `anonimizador_no_disponible`): la CLI da 0 por diseño, pero la tarea exige un código distinto de 0 con el anonimizador caído. La demo sale con 4 e imprime ese archivo con 0 hallazgos.
- **Cómo corre la CLI fuera del repositorio:** instalada como copia (`--no-editable`) desde `/workspace/.../deploy/.venv`, sin tocar `libs/` ni `contracts/`. Cargan el *prompt*, los perfiles, los contratos y el aviso. La regla del corpus no aplica (`origen: sintetico`).
- **uv en la imagen:** fijado por versión (`pip install uv==0.13.9`), sin digest ni hashes: no hay red para obtenerlos. Pendiente para el humano o la CI.
- **Imagen sin entradas:** la etapa final copia solo el entorno virtual, como pide la tarea; las entradas las monta U02-T02.
- No hay propiedad Hypothesis: `hypothesis` no está en el lock y `uv lock` exige red. La invariante «código distinto de 0 no imprime hallazgos» se cubre con casos parametrizados.
